# Sequifier v3.1.2.0

This release adds per-sequence static features and two options for preserving
small gradients in categorical models. The comparison baseline is v3.1.1.0.

## Highlights

- **Condition predictions on static features.** Preprocessing can read a
  separate CSV or Parquet table with one row per `sequenceId`. Configure
  `static_data_path` and, where needed, `static_categorical_columns` or
  `static_real_columns`. A model interface can select those columns with
  `static_conditioning`. The features are available during training, PyTorch
  and ONNX inference, and autoregressive generation.
- **Use accurate cross-entropy for categorical targets.** Set a target's
  criterion to `AccurateCrossEntropyLoss` to retain small losses and
  target-logit gradients at high confidence. It supports class weights and
  hashed target heads; hashed targets still do not support class weights.
- **Choose max-excluding softmax for composite merges.** Set
  `merge.softmax: max_excluding` on a `gated` or `attention` ingestion merge to
  retain small gradients when one branch score dominates. The default remains
  `standard`; `max_excluding` costs additional compute.
- **Clarify prediction length.** Training uses all valid decoded positions for
  loss. `prediction_length` selects consecutive output positions during
  inference; it does not make one input position predict several future events.

## Configuration and compatibility

- To use static conditioning, re-run preprocessing with `static_data_path` and
  set `model.interface.static_conditioning.columns` to the desired features.
  Static column names must be distinct from temporal inputs and targets, and
  the static and sequence tables must contain the same `sequenceId` set. For
  mixed categorical and real static features, provide
  `feature_embedding_dims` for every selected column.
- Static conditioning adds one prefix position to the backbone. Set
  `model.backbone.architecture.max_context_length` to at least
  `global_training.context_length + 1`.
- Existing configurations keep their current defaults. This release has no
  breaking configuration changes.
