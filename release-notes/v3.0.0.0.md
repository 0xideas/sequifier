# Sequifier v3.0.0.0

This release changes preprocessing configuration and stored dataset formats. It
also adds value-based splits, prediction-aligned windows, categorical hashing,
and a bundled documentation command. The comparison baseline is v2.2.0.0.

## Highlights

- **Split at explicit values.** `split_method: value_cutoff` uses `split_column`
  and ordered integer or Date/Datetime `split_values` to create boundaries.
  Values equal to a cutoff belong to the later split. Timestamp split columns
  can be retained for traceability but cannot be model inputs or targets.
  `value_cutoff` is not supported with depth layouts.
- **Align predictions with selected splits.** `prediction_aligned_splits` places
  prediction groups backward from each split's end using `prediction_length`
  and `target_offset`. Earlier rows of the same sequence can supply context;
  predictions outside the split are masked from training, metrics, and
  inference output. Other splits use distributed placement with one scalar
  preprocessing `window_stride`.
- **Fit metadata on training data by default.** With the new
  `normalize_on_all_data: false` default, numeric statistics and dynamic
  categorical vocabularies use split 0. Categories first seen in later splits
  map to `[other]`, or to a configured hash bucket fallback.
- **Control categorical cardinality.** Per-column `cardinality_config` supports
  `top_k` or `min_freq` retention and optional bounded hashing for remaining
  categories. `categorical_columns` and `real_columns` can override dtype-based
  classification, including for integer-valued numeric features.
- **Hash model inputs and targets.** Interface-level `categorical_hashing`
  supports independent `multi_hash` tables and quotient/remainder (`qr`)
  embeddings. Categorical targets use component heads whose predictions are
  resolved to canonical IDs. These model hashes are separate from preprocessing
  cardinality hashing; stored datasets need no extra hash columns.
- **Allocate categorical embedding widths by cardinality.** When
  `feature_embedding_dims` is omitted for a categorical-only ingestion, each
  column receives at least two dimensions and the remainder is distributed by
  cardinality. Explicit widths still take precedence.
- **Process large inputs with bounded buffers.** Flat preprocessing batches
  sequence windows and writes merged output incrementally. Depth preprocessing
  merges ordered item streams across files, including interleaved coordinate
  ranges, with bounded fan-in and temporary sorted runs for large file counts.
- **Read guides from the CLI.** `sequifier docs` prints the bundled
  documentation; `sequifier docs preprocess`, `train`, or `infer` prints one
  command guide.

## Breaking changes and upgrade steps

1. **Update preprocessing configs.** Replace `window_strides` with one
   `window_stride`. The old `window_placement` and `split_context` settings
   are replaced by `prediction_aligned_splits`, `prediction_length`, and
   `target_offset` when aligned placement is needed. Aligned splits require
   `target_offset == max_target_offset`, a matching decoder prediction length,
   and `global_training.window_stride: null`. Aligned inference supports
   generative, non-autoregressive output with `window_stride: null`.
2. **Re-run preprocessing.** Stored windows now include absolute start positions
   and split target bounds. Readers reject older Parquet output missing these
   fields and older PT payloads. New PT files use version 5 of the
   `sequifier_tensor_batch` envelope; legacy tuple payloads and envelope
   versions 2 through 4 are not accepted. Recreate datasets before training or
   inference with v3.0.0.0.
3. **Review fitted metadata.** The default `normalize_on_all_data: false` can
   change normalization statistics and categorical IDs compared with v2.2.0.0.
   Set it to `true` when recreating data if the previous all-data fitting
   behavior is required.
4. **Review split proportions.** Preprocessing rejects a split plan estimated
   to put less than 50% of stored windows in split 0. Set `ALLOW_LARGE_SPLITS=1`
   to permit that plan with a warning. The estimate accounts for different
   strides on prediction-aligned and distributed splits.
5. **Check categorical model settings.** Automatic embedding allocation now
   requires at least two output dimensions per categorical column; provide
   `feature_embedding_dims` to use smaller shares. The default categorical
   decoder vocabulary now includes `[other]`; use an explicit empty
   `categorical_decoder_special_tokens` list for a target to exclude it. A
   hashed target requires `CrossEntropyLoss`, cannot use `class_weights`, and
   must be last in an autoregressive decoder branch's target order.
6. **Check exact-resume checkpoints.** Run checkpoints must record both
   `initialization_policy_version: 1` and
   `initialization_seed_derivation_version: 1`. Older checkpoints without these
   provenance versions cannot be resumed.
