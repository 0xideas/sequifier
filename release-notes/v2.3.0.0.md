# Sequifier v2.3.0.0

This release adds more control over temporal splits and high-cardinality
categorical data. It also changes the format of preprocessed datasets.

## Highlights

- **Split at explicit values.** `split_method: value_cutoff` creates splits at
  integer or Date/Datetime values supplied through `split_column` and
  `split_values`. A value equal to a cutoff belongs to the later split. This
  makes time-based train/validation/test boundaries possible without relying on
  row proportions. Timestamp split columns cannot be model inputs or targets;
  `value_cutoff` is not supported with depth layouts.
- **Carry history across split boundaries.** `split_context: {mode: preceding,
  target_offset: ..., prediction_length: ...}` lets validation and test windows
  use preceding sequence rows as input. Targets outside the window's own split
  are masked from loss and metrics. The default remains `isolated`.
- **Fit preprocessing metadata on training data by default.** Numeric
  statistics and dynamic categorical vocabularies now use split 0 unless
  `normalize_on_all_data: true` is set. Categories seen only in later splits map
  to `[other]` unless a hash bucket fallback is configured. This reduces
  leakage from validation and test data.
- **Control categorical cardinality.** Per-column `cardinality_config` can
  retain categories by `top_k` or `min_freq`, with an optional bounded hash
  bucket fallback for other values. `categorical_columns` and `real_columns`
  can explicitly classify columns, including integer-valued numeric features
  that should be treated as real values.
- **Hash model embeddings and targets.** Interface-level
  `categorical_hashing` supports `multi_hash` and quotient/remainder (`qr`)
  strategies. Hashed input embeddings use smaller tables; hashed categorical
  targets use component heads and resolve predictions back to canonical IDs.
  A hashed target requires `CrossEntropyLoss`, cannot use `class_weights`, and
  must be last in an autoregressive decoder branch's target order.
- **Allocate categorical embedding widths by cardinality.** When
  `feature_embedding_dims` is omitted for a categorical-only ingestion,
  Sequifier now assigns at least two dimensions per column and distributes
  remaining dimensions according to cardinality. Explicit dimensions still
  take precedence.

Preprocessing also processes sequence windows in batches and writes merged
output incrementally, reducing the amount of intermediate data held in memory.

## Upgrade notes

- **Re-run preprocessing for existing datasets.** Stored windows now include
  absolute start positions and split target bounds. Readers reject older
  Parquet outputs without these fields and older PT payloads. New PT files use
  version 5 of the `sequifier_tensor_batch` envelope; tuple payloads and
  envelope versions 2–4 are no longer accepted.
- **Review normalization and vocabulary changes.** The new default
  `normalize_on_all_data: false` can change real-column statistics and category
  IDs compared with v2.2.0.0. Set it to `true` to retain the former all-data
  fitting behavior when recreating a dataset.
- **Check model widths and decoder vocabularies.** Automatic categorical
  embedding allocation now needs at least two output dimensions per column;
  specify `feature_embedding_dims` to use smaller shares. The default
  categorical decoder vocabulary now includes `[other]`; set an explicit empty
  `categorical_decoder_special_tokens` list for a target to exclude it.
- **Legacy checkpoint compatibility is narrower.** Checkpoints with
  `initialization_policy_version: 0` can no longer be resumed.

See the [preprocessing guide](../documentation/configs/preprocess.md) for split
and window settings, and the [training guide](../documentation/configs/train.md)
for model hashing and embedding configuration.
