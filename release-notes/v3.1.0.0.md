# Sequifier v3.1.1.0

This release extends the v3.0 preprocessing and inference contract. The
comparison baseline is v3.0.0.0.

## Highlights

- **Choose stored widths per split.** `window_lengths` accepts one physical
  window width per split. `window_length` remains available when all splits use
  the same width. Training and inference select the layout of the actual split
  and validate that it can hold the model view.
- **Evaluate several aligned prediction groups per window.**
  `prediction_alignment_steps` defaults to `1`. Values above `1` let an aligned
  stored window carry consecutive groups separated by `prediction_length`.
  Inference evaluates those groups and applies split bounds to its output.
- **Use more CPU workers during preprocessing.** Flat input metadata fitting
  and file auditing can run across files. For a single depth Parquet file with
  multiple row groups and no `max_rows`, auditing, metadata fitting, and window
  materialization can run across workers. Depth inputs outside those conditions
  continue through the ordered merge path.
- **Tighten inference metadata checks.** Folder inference checks relevant input
  and target types, category maps, normalization statistics, and layout facts
  against selected metadata. Artifact-only inference can accept a wider folder
  window when the remaining storage and semantic contract matches.

## Configuration and compatibility

- Set exactly one of `window_length` or `window_lengths`. The list must contain
  one positive width per split. `prediction_alignment_steps > 1` requires
  `window_lengths`; every width from split 2 onward must equal the first width
  plus `prediction_alignment_steps - 1`. An aligned split must have room for
  `prediction_alignment_steps × prediction_length` target positions after
  `max_target_offset`, and training and inference require enough width for
  `context_length + target_offset + (prediction_alignment_steps - 1) ×
  prediction_length`.
- Aligned inference still requires `window_stride: null`. Aligned training can
  now use `global_training.window_stride` to sample additional model views.
- Depth `sequenceId` and `itemPosition` columns must have integer source types
  that fit signed Int64. Source values previously supplied as convertible
  strings must be converted before preprocessing.
- Training now rejects missing training or validation data paths during config
  resolution. Folder inference requires `metadata.json` with category and
  normalization semantics; older folders lacking those fields must be
  reprocessed.
